# y2026-hmb
HMB — Harness–Model Benchmark

Бенчмарк связок «harness + модель» на практических задачах:
программирование, работа в терминале, Excel.
Дизайн и план: [docs/bench-001-proposal.md](docs/bench-001-proposal.md).


## 1 - Быстрый старт

### 1.1 - Общее

Требования: Python 3.9+ (PyYAML; для excel-задачи — openpyxl)  
Для запусков "run_manual": установленный VSCode extension "Claude Code"  
Для запусков "run_cli": установленный Claude Code CLI (`claude`).  
Команды запускаются из корня репозитория.  

```
python -m hmb_runner list                  # список задач
python -m hmb_runner sanity --all          # verifier'ы обязаны проходить эталонные решения
```

### 1.2 - Вариант 1: run_manual — ручной прогон через панель VSCode (бывш. `start`)

```
python -m hmb_runner run_manual <task-id>  # развернёт workspaces/<таймстемп>-<task-id>,
                                           # снимет версии, напечатает промпт для панели
# Открыть workspace в VSCode (скопировать и запустить строчку "code ...")
# Зафиксировать токены перед стартом, подготовить таймер
# Вставить промпт в панель Claude Code, запустить (вместе с таймером), дождаться завершения

python -m hmb_runner verify <task-id>      # проверит свежайший workspace задачи и допишет
                                           # результат строкой в results/journal.xlsx
# Записать в итоговую таблицу время по таймеру, потраченные токены.
# Опционально: оценить ход решения.
```

### 1.3 - Вариант 2: run_cli — автоматический headless-прогон

```
# Зафиксировать токены перед стартом, подготовить таймер
# Запустить (вместе с таймером), дождаться завершения

python -m hmb_runner run_cli <task-id> [--model <model>] [--timeout-min N]
```

Разворачивает чистый workspace и запускает в нём `claude -p` с промптом задачи
(`--output-format stream-json --verbose --dangerously-skip-permissions`,
автообновление отключено). По завершении (или по таймауту `time_limit_min`
задачи, или `--timeout-min`) сам запускает verifier и пишет результат в журнал
(`mode: "cli"`).

> **WARNING**: с `--dangerously-skip-permissions` подтверждения не запрашиваются —
> shell-команды и запись файлов выполняются свободно. Runner печатает это
> предупреждение при каждом запуске; рекомендуется изоляция (контейнер/VM).

Метрики из финального события stream-json (`<workspace>/.hmb-session.jsonl` —
полный лог сессии, артефакт прогона) попадают в запись журнала (`metrics`) и
в excel-отчёт: шаги агента (`num_turns`), время (`duration_ms`), токены
(`usage`), стоимость (`total_cost_usd`), `terminal_reason`, `session_id`.

## 2 - Подробности

Каждый прогон создаёт отдельный воркспейс `workspaces/<ГГГГММДДТЧЧММСС>-<task-id>`
(локальное время, точность до секунды), так что повторные прогоны не затирают друг друга.
`verify` без `--workspace` берёт самый свежий воркспейс задачи (режим прогона —
`manual` или `cli` — определяется по метаданным workspace).
Полезные флаги: `verify --workspace <dir>`,
`verify --notes "..." --model <model>` (метаданные прогона), `verify --no-record`
(проверить без записи). Снимок версий расширения/VSCode/CLI делается автоматически
при `run_manual`/`run_cli` и попадает в запись журнала. Журнал — общий excel-файл
`results/journal.xlsx` (лист «Журнал», одна строка на прогон; нужен openpyxl).
Если журнал заблокирован на запись (открыт в Excel), любая команда отказывает
на старте; если блокировка возникла прямо во время прогона, результат
записывается во временный `journal-DRAFT-<ГГГГММДДТЧЧММСС>.xlsx` — потом его
строку надо перенести в основной журнал.
Кроме журнала, `verify` формирует индивидуальный excel-отчёт прогона
`results/report-<ГГГГММДДТЧЧММСС>-<task-id>.xlsx`: лист «Статистика» (score, время,
модель, версии, метрики CLI-прогона и т.п.) и лист «Ошибки» со списком проваленных
проверок.

## 3 - Структура

- `tasks/<category>/<task-id>/` — `task.yaml` (промпт, настройки), `env/` (стартовый
  workspace), `verify/` (автопроверка, печатает `SCORE: <доля>`; может дописывать
  детальные кейсы одной jsonl-строкой в файл из `$HMB_DETAILS` — попадают в лист
  «Кейсы» excel-отчёта), `solution/` (эталон для `sanity`), `tools/` (генераторы
  данных с фиксированным сидом)
- `hmb_runner/` — CLI прогона: `list / run_manual / run_cli / verify / sanity / snapshot`
- `suites/core.yaml` — набор задач v0 (по одной на категорию)
- `results/`, `workspaces/` — журнал прогонов и рабочие папки (в git не входят)
